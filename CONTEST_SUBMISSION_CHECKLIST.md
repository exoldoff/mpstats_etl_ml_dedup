# Contest Submission Checklist

* [ ] README актуален
* [ ] Docker собирается
* [ ] Проект запускается с нуля
* [ ] Ноутбуки открываются
* [ ] Данные не содержат приватной информации
* [ ] Секреты не попали в репозиторий
* [ ] Основные результаты ML описаны
* [ ] Есть инструкция для жюри
* [ ] Есть список известных ограничений

## Перед отправкой

* [ ] Открыть `README.md` на GitHub и проверить, что схема
  `docs/assets/ml_dedup_pipeline_flow.svg` отображается.
* [ ] Запустить `docker compose build && docker compose up`, открыть
  `http://127.0.0.1:8055/api/health`.
* [ ] Запустить классический launcher `.command` или `.bat` на чистой машине.
* [ ] Проверить `git status --short`: в коммит попали только конкурсные
  правки, без `.env`, DuckDB, CSV/XLSX и model cache.
* [ ] Принять решение по outputs в `notebooks/04_fusion_pack_grouping.ipynb`:
  оставить как защитную визуализацию или очистить/перегенерировать.
* [ ] В чистом UI создать или импортировать справочник категорий и правила
  классификатора перед демонстрацией реального pipeline.
* [ ] Проверить, что первый ML-дедуп имеет доступ к сети для скачивания
  Hugging Face моделей или заранее подготовленный model cache.

## Известные ограничения

* [ ] В чистом репозитории нет пользовательской DuckDB, MPStats cookie,
  рабочих CSV/XLSX и model cache.
* [ ] Docker стартует с пустыми runtime CSV, если справочник и правила не
  импортированы через UI.
* [ ] CI пока не настроен; проверки запускаются локальными командами из
  audit-файла.
